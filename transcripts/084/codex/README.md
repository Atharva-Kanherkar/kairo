# 084 Codex consumer-boundary evidence

Run on 2026-09-24 UTC with the real Codex CLI 0.156.1 (`npm install @openai/codex@0.156.1`), model `gpt-5.6-luna`, LiteLLM Proxy 1.102.1, and the live OpenAI API.

## Rig

```text
Codex -> client tap :9998 -> LiteLLM :4010 -> upstream tap :9997 -> api.openai.com
Codex -> direct tap :9999 -> api.openai.com            (no-gateway control)
```

- `tap.py` is a logging HTTP forwarder. It records every request and response and redacts credential headers inline. It passes the client's `Accept-Encoding` through unchanged. It does not proxy WebSockets, so Codex logs a 403 and falls back to HTTPS on every run. That fallback is a rig artifact and does not affect search.
- LiteLLM runs with `litellm.yaml`, `LITELLM_MASTER_KEY=sk-review-master` (synthetic), and `OPENAI_API_BASE` pointing at the upstream tap.
- The direct tap replaces Codex's dummy bearer with `OPENAI_API_KEY`, so the real key is never written into a Codex home.
- Each case uses a fresh temporary `CODEX_HOME`, runs `codex exec` in a read-only sandbox, and asks for a web search.

## What is committed

- `runs/<case>/search/`: every `/v1/alpha/search` exchange in full. `client-NN` is what Codex sent to LiteLLM and what LiteLLM returned; `upstream-NN` is what LiteLLM forwarded to OpenAI and what OpenAI returned; `direct-NN` is the no-gateway control. gzip bodies are decompressed.
- `runs/<case>/exchanges.json`: method, path, and status for every request on every hop.
- `runs/<case>/stdout.txt`: Codex's final answer.
- `runs/<case>/stderr-search-lines.txt`: the Codex banner and every web search and tool router line, including the provider's 400.
- `runs/<case>/codex-args.txt`: the exact `codex exec` arguments.

## What is not committed, and why

- Codex `/v1/responses` bodies and the full Codex stderr. They include local environment content that Codex loaded or read, such as skill paths and file contents from the test machine. `export.py` records only whether the `web.run` search tool was offered (`web_run_tool_offered`).
- Redacted inline as `[REDACTED]`: `authorization`, `api-key`, `cookie`, `set-cookie`, OpenAI organization and project headers, and Codex session, thread, window, and turn metadata headers. The `id` field under dispute is never redacted.
